# Review and merge practice

Open **Files changed** and read every line as text. Do not download or run anything.

1. Does the title describe the change?
2. Can a first-time learner follow the steps?
3. Is the base repository clear?
4. Are there only expected Markdown edits, with no sensitive or restricted content?
5. Offer one actionable comment: identify the confusing phrase, explain the missing context and suggest a small improvement. Critique the text, not the author.

The author replies, makes another commit on the same branch and explains the correction. The reviewer verifies the updated diff. Request changes for unresolved issues; approve only content actually inspected.

For a fork rehearsal the owner may merge after self-checking, but label it self-reviewed. For upstream, required checks and authorized maintainer review control merging. If you cannot merge, wait for the responsible person; do not bypass protections. After merging, inspect the target branch to confirm the file exists.
