# Project planning kit

Start with the [project plan](PROJECT_PLAN.md), then explain the [architecture](ARCHITECTURE.md) and [test plan](TEST_PLAN.md). Record significant decisions with an [ADR](ADR_TEMPLATE.md).

Use [tasks](TASKS.md) for small reviewable milestones, [contributors](CONTRIBUTORS.md) for agreed roles, and the [roadmap](ROADMAP.md) to distinguish planned work from shipped behavior. Before a release, inspect the [security checklist](SECURITY_CHECKLIST.md) and [release checklist](RELEASE_CHECKLIST.md). Reflect using the [retrospective](RETROSPECTIVE.md).

These are blank planning aids, not completed community projects. Keep source in your own repository and use [submission evidence](../SUBMISSION_EVIDENCE.md) when ready for review.
