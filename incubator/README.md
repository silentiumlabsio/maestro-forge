# Project Incubator

The Incubator supports project proposals, the Idea Marketplace, Find a Builder, Review Exchange, open roles, community requests, and one recurring Community Project.

Project states are `idea`, `recruiting`, `building`, `review`, `shipped`, and `archived`. Source stays in a contributor-owned repository unless maintainers explicitly approve a focused core contribution.

Use GitHub issue forms to propose a project or idea, opt in to the builder directory, or request review. Do not publish fake teams, activity, roles, or progress. Community Project code follows the same zero-trust contribution boundary as every other submission.


## From idea to a reviewable project

1. Check existing issues for duplication. Open [a project proposal](https://github.com/silentiumlabsio/maestro-forge/issues/new?template=community-project.yml) or [an idea](https://github.com/silentiumlabsio/maestro-forge/issues/new?template=idea-proposal.yml).
2. Define one user, one problem, a small deliverable, non-goals, ownership, license, data boundaries and a stopping condition. Use [the planning kit](../templates/README.md).
3. Mark recruiting only when there is a scoped task and a responsible owner. Use [Open role](https://github.com/silentiumlabsio/maestro-forge/issues/new?template=open-role.yml); do not request credentials or private contact details.
4. Work in a contributor-owned repository. Keep task status and decisions visible; do not imply a proposal has shipped.
5. At a milestone, request [focused review](https://github.com/silentiumlabsio/maestro-forge/issues/new?template=review-request.yml), then submit exact-commit evidence for any showcase request.

No active team, recurring Community Project or shipped incubator product is claimed here. To archive an abandoned proposal, explain the decision and preserve useful public-safe lessons. A collaborator's access should be the minimum needed and removed when no longer needed.
