# Open Source Builder

Learn GitHub contribution flow, documentation, collaboration, schemas, and transparent scoring.

[All paths](README.md) · [Challenge catalog](../challenges/README.md)

## Before you start

Complete the First PR Sandbox first. Practice the entire loop in your fork before proposing upstream changes.

## Suggested sequence

1. [B08 — Project README Builder](../challenges/beginner/b08-project-readme-builder/README.md) — Create a small tool that asks project questions and generates a clean README draft.
2. [I03 — Repository Activity Dashboard](../challenges/intermediate/i03-repository-activity-dashboard/README.md) — Build a dashboard using public GitHub API data for stars, issues, and recent activity.
3. [I08 — Challenge Progress Board](../challenges/intermediate/i08-challenge-progress-board/README.md) — Build a static dashboard that reads challenge metadata and shows status, owner, and completion progress.
4. [A05 — Challenge Catalog Compiler](../challenges/advanced/a05-challenge-catalog-compiler/README.md) — Build a schema-driven compiler that validates challenge manifests and generates indexes/pages.
5. [A07 — Contribution Reputation Engine](../challenges/advanced/a07-contribution-reputation-engine/README.md) — Create a transparent contribution scoring prototype using merged GitHub activity without turning it into a popularity contest.

## Checkpoints

- Foundation: explain the input contract and show a normal case plus invalid input.
- Applied: demonstrate a failure, a regression check and documented data boundaries.
- Synthesis: compare design alternatives, show reproducible evidence and identify remaining limitations.

Pause or skip ahead based on your needs. Completing a list does not confer certification or automatic verification. Use the [evidence template](../templates/SUBMISSION_EVIDENCE.md) and request focused review after a useful milestone.
