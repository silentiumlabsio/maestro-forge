# Web Builder

Build accessible, local-first browser experiences with careful state and API boundaries.

[All paths](README.md) · [Challenge catalog](../challenges/README.md)

## Before you start

Know basic HTML and JavaScript functions. Use keyboard-accessible controls and synthetic browser data.

## Suggested sequence

1. [B03 — Pomodoro Web App](../challenges/beginner/b03-pomodoro-web-app/README.md) — Build an accessible browser-based Pomodoro timer using plain web technologies.
2. [B04 — Grade Scenario Calculator](../challenges/beginner/b04-grade-scenario-calculator/README.md) — Create a calculator that helps a student estimate course outcomes from weighted categories.
3. [I03 — Repository Activity Dashboard](../challenges/intermediate/i03-repository-activity-dashboard/README.md) — Build a dashboard using public GitHub API data for stars, issues, and recent activity.
4. [I05 — Offline Flashcard PWA](../challenges/intermediate/i05-offline-flashcard-pwa/README.md) — Create an installable flashcard web app that works offline.
5. [I08 — Challenge Progress Board](../challenges/intermediate/i08-challenge-progress-board/README.md) — Build a static dashboard that reads challenge metadata and shows status, owner, and completion progress.
6. [A02 — Offline-First Course Dashboard](../challenges/advanced/a02-offline-first-course-dashboard/README.md) — Design a modular course dashboard that remains useful offline and syncs only when explicitly configured.

## Checkpoints

- Foundation: explain the input contract and show a normal case plus invalid input.
- Applied: demonstrate a failure, a regression check and documented data boundaries.
- Synthesis: compare design alternatives, show reproducible evidence and identify remaining limitations.

Pause or skip ahead based on your needs. Completing a list does not confer certification or automatic verification. Use the [evidence template](../templates/SUBMISSION_EVIDENCE.md) and request focused review after a useful milestone.
