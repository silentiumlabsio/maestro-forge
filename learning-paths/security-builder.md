# Security Builder

Practice safe configuration, validation, static analysis, privacy, and threat modeling.

[All paths](README.md) · [Challenge catalog](../challenges/README.md)

## Before you start

Be comfortable with functions and reading errors. If new to code, begin with a beginner challenge and one passing test.

## Suggested sequence

1. [B07 — Secret-Safe Config Demo](../challenges/beginner/b07-secret-safe-config-demo/README.md) — Build a tiny app that reads configuration from environment variables without hardcoded secrets.
2. [I07 — Secure Starter App](../challenges/intermediate/i07-secure-starter-app/README.md) — Create a small web/API starter with input validation, tests, and documented security defaults.
3. [A03 — Static Contribution Risk Linter](../challenges/advanced/a03-static-contribution-risk-linter/README.md) — Create a static linter that flags risky patterns in submitted source without executing it.
4. [A06 — Learning Telemetry Dashboard](../challenges/advanced/a06-learning-telemetry-dashboard/README.md) — Design privacy-conscious local telemetry for study sessions and visualize trends.
5. [A08 — Sandbox Design Challenge](../challenges/advanced/a08-sandbox-design-challenge/README.md) — Design and prototype a safe evaluation architecture for untrusted student code without executing submissions on maintainer infrastructure.

## Checkpoints

- Foundation: explain the input contract and show a normal case plus invalid input.
- Applied: demonstrate a failure, a regression check and documented data boundaries.
- Synthesis: compare design alternatives, show reproducible evidence and identify remaining limitations.

Pause or skip ahead based on your needs. Completing a list does not confer certification or automatic verification. Use the [evidence template](../templates/SUBMISSION_EVIDENCE.md) and request focused review after a useful milestone.
