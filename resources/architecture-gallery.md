# Architecture Gallery and Build Journals

Architecture entries should explain context, components, data flow, external dependencies, trust boundaries, failure modes, and security decisions. Diagrams must be accessible through equivalent text.

Build journals should record the problem, decisions, experiments, failures, review feedback, changes, and next steps. Do not fabricate timelines or outcomes and do not expose private repositories, local paths, credentials, or student data.

Screenshots are supporting evidence, never a substitute for a working accessible interface or a reviewed repository link.
