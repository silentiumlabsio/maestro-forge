# Official Challenge Standard

Every official Silentium Labs challenge must be useful enough to show in a portfolio and small enough to finish within its stated scope.

Required fields:

- stable ID (`B##`, `I##`, `A##`);
- title and version;
- difficulty;
- track/category;
- estimated effort band (not a promise);
- prerequisites;
- mission;
- learning objectives;
- functional requirements;
- security requirements;
- acceptance criteria;
- required deliverables;
- allowed or suggested languages;
- dependency constraints;
- public tests where appropriate;
- reviewer verification prompts/variant ideas;
- stretch goals;
- authorship credit;
- changelog.

## Quality rules

- Avoid trivia-only exercises.
- Beginner does not mean meaningless.
- Prefer projects with visible output or useful behavior.
- Teach one primary skill and a small number of supporting skills.
- State what is intentionally out of scope.
- Do not require paid services for core completion.
- Provide a local/synthetic target for security exercises.
- Never direct students to test real third-party systems without authorization.
