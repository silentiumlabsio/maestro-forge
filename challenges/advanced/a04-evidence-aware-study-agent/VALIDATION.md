# A04 validation

These are test specifications, not claims that an implementation passed. Run checks in your own solution repository; record the exact commit and actual outcome.

## Small example

Use [input.json](examples/input.json) as synthetic data. This claim is evidence-backed by demo-a; a claim about exam outcomes is unsupported. Never manufacture a citation.

## Boundary and failure checks

Create an evaluation set with supported, inferred, contradictory, absent and injection-bearing cases. Report observed category errors separately from interpretation.

## Review prompts

- Explain: Return evidence, inference or unsupported with source IDs and a reason.
- Debug: choose one boundary case above, reproduce it, and fix the cause.
- Adapt: change one input constraint, update its validation and show the changed result.

These checks supplement the brief and versioned rubric; they do not replace human review or prove security.
